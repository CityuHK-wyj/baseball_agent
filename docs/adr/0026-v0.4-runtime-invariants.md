# ADR 0026: v0.4 runtime invariants — frozen correctness rules for the Artifact runtime

- Status: Accepted
- Date: 2025-10-01
- Corrects (does not replace): 0025 Artifact runtime
- Related: 0002 contextual artifact assessment, 0007 operational stores and checkpoints,
  0018 evidence extraction, 0020 analytical population and qualification,
  0019 shared knowledge base

## Context

The independent v0.3 architecture review (`codex/v0.3-architecture-review @ 0ee26ea`,
`docs/reviews/v03-full-architecture-review/REPORT.md`) returned
`ARCHITECTURE_REVIEW_CHANGES_REQUIRED`. The review judged the architecture *direction*
sound — flexible cognition, composable evidence, deterministic privileged actions,
contextual evaluation, governed knowledge — but found that the implementation did not yet
establish trustworthy runtime truth:

1. evidence scope truth (a Tool could certify its own requested scope; rosters were
   exempted from temporal checks);
2. independent Judge authority (the independent hook was only consulted for weak
   candidates and could never veto an apparent `SATISFIED`);
3. action/IR fidelity (aliases could inject SQL structure; accepted IR constructs were
   silently ignored);
4. recovery feedback (`local_analytics` failures could disappear from planning and trace);
5. generic Artifact composition (ambient export injection instead of explicit bindings);
6. persistence/resume identity (counters not restored; refs could be overwritten);
7. final claim grounding (pointers treated as entailment; causal claims unchecked).

v0.4 is **another correction of the existing architecture**, not a brand-new architecture.
The Interaction / Planning / Tools / Evaluation / Response layers and all existing security,
persistence and governance boundaries are preserved.

## Decision

Freeze the following invariants as the runtime contract. Code implementing them lives
under `app/artifact_runtime/` with contracts in `app/models/artifact_runtime.py`.

### Invariant 1 — Requested scope cannot certify evidence scope

`RequestedScope` (what the user/Need requires), `DeclaredScope`
(`RuntimeArtifact.actual_scope`, what the Tool/provider claims) and
`ScopeVerification` (what deterministic/provider/execution evidence establishes) are
distinct. Only `verify_artifact_scope` produces verification. A declared value that merely
echoes the request can reach `PARTIAL`, never `VERIFIED`. `UNKNOWN` never becomes coverage.
Dimensions: entity, population, membership, time, season, game type, event population,
measure, aggregation, qualification, source coverage.

### Invariant 2 — Planner cannot approve its own completion baseline

`Goal.obligations` is an immutable/frozen baseline derived from the user message and
confirmed clarification (`extract_obligations`). Planner Needs are checked against it.
COMPLETE requires every core obligation to be covered by verified, judged work; a Planner
declaration alone (`Need.satisfies_obligations`) is insufficient.

### Invariant 3 — Independent assessment participates in every evidence loop

`CoverageJudge` combines deterministic verification and an `IndependentJudge`. The Judge is
consulted on *every* candidate, including apparently sufficient ones. It may downgrade but
may never override a deterministic hard mismatch. Judge outage becomes an explicit
`assessment_available = False` (forcing `PARTIAL`), never automatic success.

### Invariant 4 — Every attempted action has a durable outcome

`ToolOutcome`/`ToolAttempt` use the taxonomy `SUCCESS, EMPTY_RESULT,
UNSUPPORTED_CAPABILITY, INPUT_UNRESOLVED, INPUT_INCOMPATIBLE, INVALID_IR, UNKNOWN_FIELD,
SCOPE_MISMATCH, COVERAGE_UNAVAILABLE, SOURCE_TRANSIENT, POLICY_BLOCKED, MODEL_UNAVAILABLE,
INTERNAL_FAILURE, INTERRUPTED, UNCERTAIN`. Every request produces an attempt, persisted
before and after execution. No-Artifact failures are first-class and become Planner gaps.

### Invariant 5 — Artifact bindings must be explicit

A downstream action binds only exports from its declared dependencies
(`bindings.resolve_bindings`); ambient export injection is removed. Prior-turn, wrong-team,
rejected, stale or partial artifacts cannot bind by export type alone.

### Invariant 6 — Accepted IR semantics equal executed semantics

Model-controlled identifier slots (aliases, order-by tokens) must match
`^[A-Za-z_][A-Za-z0-9_]{0,63}$`. Every accepted aggregate/condition/period combination is
implemented or explicitly rejected. Catalog `allowed_operations`, roles and types are
enforced. The declared window is compiled into the executed predicate. Qualification uses
the measured denominator, not raw row count. The existing SQL AST guard remains.

### Invariant 7 — Wrong-scope evidence cannot satisfy a core obligation

Scope comparison is dimension-aware and uses verified statuses. Blanket exceptions
(roster temporal exemption, measure-family equivalence as identity) are removed. The active
roster provider is `MISMATCH` for requested historical/official membership.

### Invariant 8 — Tool capability contracts must be truthful

`ToolCapabilityContract` declares temporal modes, population modes, game types, entity
namespace, supported measures, availability, authority and cost. The Planner may only
propose compatible actions; the Tool rejects unsupported inputs defensively.

### Invariant 9 — Stable identity and lineage survive restart

`ArtifactStore`/`ReferenceStore` never reuse an id, including after restore. Execution
intent is persisted before side effects. Uncertain external work is never auto-retried.
Persistence failures are surfaced (`persistence_error`, `PERSISTENCE_ERROR` event), not
swallowed.

### Invariant 10 — Candidate Knowledge is never authoritative automatically

Normal authoritative retrieval is ACTIVE-only and excludes pending candidates. Promotion
preserves category, scope, language/locale/community, evidence spans, originating run and
reviewer. Conflicts are structured records with exact IDs; an unavailable conflict check
fails closed; promotion is idempotent.

## Consequences

- New modules: `scope_verification`, `obligations`, `judge`, `state`, `bindings`,
  `recovery`, `events`, `contracts`.
- `RuntimeTrace` now projects an append-only redacted `EventJournal`; `--trace` renders
  steps, attempts, obligations and events, so a failed action is diagnosable.
- Exports carry typed/versioned `ExportContract`s; `ArtifactExport.value: Any` is no longer
  the only semantic contract.
- Claims carry a `claim_type`; causal/inferential claims require narrative evidence and are
  otherwise downgraded to `HYPOTHESIS`.
- Normal product CLI wires `SqliteOperationalStore`; the advertised runtime is resumable.

## Security boundaries (unchanged and required)

`baseball_readonly`, read-only PostgreSQL transactions, the SQL AST guard, the
SchemaCatalog allowlist, DuckDB sandbox/path restrictions, SSRF checks (now also applied to
every redirect destination), env-only credentials, permission/cost boundaries, run
isolation, redaction and bounded execution are not weakened by v0.4.
