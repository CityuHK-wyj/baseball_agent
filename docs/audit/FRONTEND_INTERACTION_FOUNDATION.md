## Decisions / repository changes

No existing API or frontend; existing entrypoint is synchronous `Engine.ask`, `ConversationManager` uses persisted SQLite `ConversationState`, the Judge authorizes Claims and artifacts, `AnswerPackage` is internal to the Composer. Added a **thin** FastAPI adapter (`app/api/{contracts,presentation,main}.py`) and `frontend/` (React, TypeScript, Vite, React Router, Tailwind, shadcn-style Radix/CVA Button, TanStack Query/Table, Zod, Recharts, Vitest/RTL, Playwright; npm lockfile). Python `requirements.txt` adds FastAPI/Uvicorn. No alternate interpreter, planner, judge, SQL/IR compiler or Redux/Next/GraphQL/WebSockets. Frontend state is not factual authority.

`POST /api/conversations` creates a persisted conversation; `GET /api/conversations/{id}` reads persisted text/pending clarification and retained in-process events. `POST /api/conversations/{id}/messages` `{text}` → 202 `{message_id,run_id}`. `POST /api/conversations/{id}/clarifications/{clarification_id}/responses` `{selected_option_ids,free_text}` → 202 run IDs. `GET /api/runs/{run_id}/events` → SSE; `/openapi.json` defines public Pydantic schema. Backend holds the opaque option-ID → backend-provided label mapping; client sends no entity IDs/Requirements. Concurrent commands and stale/invalid clarifications are rejected. One Engine runs under a lock because its Judge/LLM are mutable.

`AgentEvent` v1 is a Pydantic discriminated union: version, type, event id `<run>:<sequence>`, conversation/run/message IDs, UTC timestamp, typed payload. Types: `run.started`, `message.accepted`, `agent.status`, `assistant.delta`, `clarification.required`, `clarification.resolved`, `artifact.created`, `answer.partial`, `answer.completed`, `run.failed`. `ClarificationRequest`: stable `clar:<goal_id>` ID, conversation/run/goal IDs, question, reason, blocking requirement IDs, opaque options, free-text permission, status; response: selected IDs **or** free text. `AnswerView`: backend status, text, limitations, backend-classified execution notices, Requirement coverage, typed presentation artifacts. Artifact envelope: id, type, title, description, status, evidence refs, scope, calculation labels, payload. `TablePayload` contains typed columns, scalar rows, total rows, pagination intent; `ChartPayload` defines bar/line/scatter axes and rows. A database table is emitted **only** when an admitted Judge Claim references that exact non-rejected artifact. SQL, execution receipts, IR, rejected artifacts and keys are not sent. Evidence/scope and Requirement coverage use progressive disclosure; no chain-of-thought.

SSE replays events strictly after `Last-Event-ID` or `after` and ends on terminal event; malformed cursors fail. Reducer dedupes events by ID, never duplicates text deltas or artifact IDs; reconnection resumes from last validated event. Unknown future event types are ignored safely; malformed **known** events or responses produce diagnostics in the UI. The browser caches snapshots via Query, not as authority. Browser event state does not interpret role, identity, dates, qualification, measure, scope or truth. Statuses are displayed verbatim, including COMPLETE, LIMITED, WAITING_FOR_USER, FAILED; protocol reserves PARTIAL for a future authoritative backend status. The present Judge returns LIMITED for mixed support, not PARTIAL. A previously approved table remains visible when a later run is limited or waiting. Table sorting, filtering, visibility and pagination are client-side; future server pagination can extend this envelope. Recharts renders typed chart intents; specialized strike-zone/spray/heat-map renderers can be added without changing the semantic core.

## Review / limitations

- No Engine callback for token-by-token *provisional* safe text: live status and run start stream immediately, the **approved final** answer arrives as a single delta after `ask` finishes. Do not present this as model token streaming. Runtime subphase statuses are not exposed; only real adapter state `interpreting` is emitted. Streaming Planner/Tool telemetry requires a separate approved Engine callback.
- Current environment: PostgreSQL unavailable, 2015–2023 Parquet available. `Luis Castillo 2025` did not produce a clarification or local result here because player directory requires PostgreSQL. The real contextual ambiguity flow above worked instead. Attempts to combine 2023 batting performance + unsupported RBI in **one** Goal yielded LIMITED with zero approved tables; the Judge did not authorize an A-only table. We did not invent one. Existing limited-after-supported-turn E2E verifies preservation, not same-Goal A+B admission. True same-Goal partial table remains contingent on backend Judge support.
- Event replay is in-process, not durable across restart or shared between workers; persisted conversation text/pending clarification survives, but historical table artifacts from prior process do not. Cancellation/idempotent retry not supported. No authentication, rate limiting, CSRF policy or multi-worker coordination: local dev only, **do not expose publicly**. Build/same-origin proxy is a future production option. Unexpected provider exceptions are sanitized as `run.failed/run`; known ToolOutcome codes are mapped on the server to structured provider/unsupported/semantic/validation notices, but these are not separate live Tool events. Judge limitations still report unresolved cases. Detailed debug Tool calls/evidence lineage beyond bounded coverage, server pagination, metric/evidence artifact renderers and specialized charts remain future work. No secrets/SQL are packaged into `frontend/` or exposed by the presenter; production security review required before hosting.
- Review found and repaired an initially non-persisted empty conversation and a missing browser library dependency before E2E. Frontend Zod known-event payloads fail closed; unknown versions fail with diagnostics. OpenAPI generation is checked in and drift-tested; TS witnesses compare known events, clarifications and tables against generated types.
